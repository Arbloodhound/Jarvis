## How the brain routes (on-device, the default)
Three models:
- **main thinker:** Qwen3-4B abliterated, file about 2.4 GB;
- **action model ("librarian" in code):** Qwen3-1.7B, file about 1.0 GB. It does tools and screen steps;
- **cloud:** off by default (`cloud_brain` pref).

The speed boost draft model is Qwen3-0.6B, off by default (Settings).

Order in `Brain.kt` (on-device branch, around line 575):
1. `OfflineNav.opensAppFirst` and `offlineNavTask` → **screen driver** (`OfflineNavigator`). Covers "open X and …" and "go on Google and search …".
2. `LocalToolCall.offlineRoute` → `runLocalLoop`:
   - `FastCommand` handles obvious commands with no model run;
   - otherwise the action model picks one tool;
   - compound requests chain (`continueLocalChain`, `MAX_CHAIN = 4`). A chain stops on a repeated web lookup (`repeatsJob`) and resumes after a Confirm tap.
3. The screen driver (any other screen job).
4. `ScreenAsk` → "needs cloud" message.
5. Otherwise a text answer.

Tools: `LocalToolCall.TOOLS` (40 on-device); the cloud catalog has 53 (`assets/ultra.manifest.json`, kept in parity by `ToolWiringTest`). Every call goes through `gate/Gate.kt`.
