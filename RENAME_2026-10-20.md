## What could NOT be executed, and why

**`.github/workflows/*` content updates.** The rename's API token cannot write workflow
files (no `workflow` scope): `POST /git/trees` carrying a `.github/workflows/release-apk.yml`
entry returns `403 "Resource not accessible by personal access token"` (verified in
isolation; a control file in the same call succeeds). Both workflow files therefore still
reference `ultra-native/` (path filters, `working-directory`, script paths, cache keys) and
one comment names `ultra_vlm.cpp`/`ultra_llm`. The exact mechanical fix is specified in
`HANDOFF_RENAME_2026-10-20.md` — **until it lands, CI on the merged tree points at a
directory that no longer exists.**

## Fresh-install consequences (restated)

The new `applicationId` `com.agent.jarvis` is a **different app** on the phone: it installs
alongside the old one; the old app and its data stay put, untouched and unreadable by the new
app. Settings reset; the memory database (`jarvis.db`) starts empty; downloaded models
(multi-GB) re-download; every per-package system grant must be redone (accessibility
service, notification listener, device-owner/Shizuku bindings); Obtainium tracks by package
id, so its feed must be re-pointed. The old app can be uninstalled once the new one is set up.
