## 1. What the repo is

`Arbloodhound/Jarvis` is one repository with three apps and a pod kit:

- `jarvis-native/` — the Android app (Kotlin), the shipping app, with the harness package `com.agent.jarvis.harness`.
- `desktop/` — Jarvis Desktop (TypeScript, Node 22, Electron): agent loop, safety gate, local or Claude brain, tools, local gateway + chat page, CLI (`jarvis chat` / `ask` / `serve`).
- `src/` — the TypeScript app of the Expo / React Native lineage.
- `tools/runpod/` — **new**: `start.sh`, the one-command self-hosted rig (see `tools/runpod/README.md`).

This session worked only in `desktop/` and the pod kit.

## 2. The self-hosted rig (MEASURED on the owner's RunPod B300, 2026-10-21)

- GPU: NVIDIA B300 SXM6 (`sm_103`, ~269 GiB usable), driver 595.91, CUDA 13.2.
- Brain: GLM-5.2-abliterated UD-Q2_K_MXFP4 on llama.cpp `b11785` (built with CUDA 12.9), 6 slots × 64K context, q8_0 KV, `--load-mode dio`. VRAM 259 / 269 GiB used.
- Vision: Qwen3-VL-8B abliterated Q4_K_M + mmproj, `-c 8192`.
- Virtual desktop over noVNC with Chrome (SearXNG search, debug port 9222), Tor Browser, Files, Editor, Terminal, Calculator, and the Jarvis app (Electron).
- Tor on 9050; SearXNG on 8890; Timestral forecasting server on 8095 (CPU).
- Jarvis config on the pod (`~/.jarvis/config.json`): `autoApprove: true`, `maxTurns: 60`, `nli.enabled: false`, `tor: { enabled: false, auto: true }`, `screenControl.enabled: true`, `vision.enabled: true`, `subagents.maxConcurrent: 4`, `local.contextTokens: 65536`, `forecast.baseUrl: http://127.0.0.1:8095`.
- Timestral on the pod answered a 12-point weekly series with a 4-step forecast that followed its 4-week cycle (≈101, 130, 143, 126, with 10–90% ranges).

## 5. How to apply the features to a running pod (no model reload)

```bash
cd /root/jarvis && git checkout -q -- . && git clean -fdq desktop/src desktop/test desktop/forecast && rm -f /workspace/patches/*.patch
curl -fsSL https://github.com/Arbloodhound/Jarvis/compare/main...claude/terminal-always-allow.diff -o /workspace/patches/1-always-allow.patch
curl -fsSL https://github.com/Arbloodhound/Jarvis/compare/main...claude/tor-auto.diff -o /workspace/patches/2-tor-auto.patch
curl -fsSL https://github.com/Arbloodhound/Jarvis/compare/main...claude/forecast.diff -o /workspace/patches/3-all-new-features.patch
for p in /workspace/patches/*.patch; do git apply "$p" && echo "applied $(basename $p)"; done
cd desktop && npm run build
```

Then `/refresh` in `jarvis chat` (first time after these patches: quit and start `jarvis chat` once). Once the PRs merge, these patches become unnecessary: `start.sh` clones `main`.
