## How the brain routes (on-device, the default)
Three brains:
- **main thinker:** Qwen3-4B Thinking abliterated;
- **action model:** small Qwen3 1.7B. It does the tools and screen work, and falls back to the main model when RAM is short;
- **cloud:** off by default (`cloud_brain` pref; `NetPolicy.cloudBrainOn`). The `offline_only` privacy switch is separate and also defaults to off.

Order in `Brain.kt` (on-device branch, around line 570):
1. `OfflineNav.opensAppFirst(req)` and `offlineNavTask` → **screen driver** (`OfflineNavigator`). Covers "open X and …" and "go on Google and search …". The app must be installed.
2. `LocalToolCall.offlineRoute` → `runLocalLoop`:
   - `FastCommand.match` handles obvious commands with no model run (flashlight, wifi, volume, battery, screenshot, call/answer/hang up…);
   - otherwise `thinkingToolCall` → `runLocalCall`;
   - compound requests chain up to `MAX_CHAIN = 4` (`continueLocalChain`).
3. `offlineNavTask` → screen driver.
4. `ScreenAsk.matches` → "needs cloud" message.
5. Otherwise a text answer.

Tools: the on-device set is `LocalToolCall.TOOLS` (40). The cloud catalog has 53 (`assets/ultra.manifest.json`). `ToolWiringTest` enforces that dispatch and the manifest match. Every call goes through `Gate.enforceCall`: risky actions get a Confirm card, password fields are blocked, OTPs are scrubbed, and a locked phone only runs harmless requests (`LockedPolicy`).
